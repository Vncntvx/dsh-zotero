# 产品模型

dsh-zotero 围绕本机的 Zotero 文献库运行。模型走工具，人走界面，通过两个入口和两套视图分工协作，底层由四个组件支撑。

## 两个入口

系统为模型和用户提供独立的交互入口：

| 入口           | 使用者  | 交互方式                             | 职责                                                                        |
| :------------- | :------ | :----------------------------------- | :-------------------------------------------------------------------------- |
| **Agent 工具** | AI 模型 | 模型工具调用（Function Calling）     | 在对话中检索、阅读原文、定位出处片段、生成引用；经审批后修改文献库。        |
| **用户界面**   | 用户    | 浏览器界面（右侧面板与会话顶部标签） | 浏览整个文献库、筛选条目、阅读 PDF、复制引用；核对 Agent 调用的文献与出处。 |

### 互不代理原则

两条路径各司其职，互不代理：

- **界面不直接调用工具**：面板里的「提问」「加入对话」只负责把条目信息填入输入框，发不发送、怎么提问由用户决定；Web 界面没有直接触发模型工具的通道。
- **工具调用不干扰界面**：Agent 在后台调用工具检索或阅读文献，不会改变用户在文献面板中选中的条目、合集树展开状态或滚动位置。

## 两个视图

本地 Zotero 是唯一的数据源。界面上提供两个视图，一个用来找文献，一个用来核对 Agent 做过的事：

| 视图         | 位置           | 定位                                                                                                      | 数据来源                              |
| :----------- | :------------- | :-------------------------------------------------------------------------------------------------------- | :------------------------------------ |
| **文献面板** | 右侧边栏       | **全局库视图**：供用户查阅与取用。浏览合集树、标签、保存的搜索与回收站，查看条目详情并阅读 PDF。          | 本地 API（通过 `zoteroLibrary` 服务） |
| **文献轨迹** | 会话顶部标签页 | **会话核对视图**：供用户核对 Agent 的工作。列出当前会话中检索的文献、查询参数、提取的原文片段与导出记录。 | 本会话的工具调用快照                  |

两处互不重叠：文献面板不记录 Agent 做过的事，文献轨迹也不提供全库浏览与编辑。

DSH 自带的「系统轨迹」记录工具调用的耗时与原始参数；「文献轨迹」只关注文献本身，展示查询条件、原文片段与导出记录。

## 四个组件

插件拆分为四个职责不同的组件：

| 组件名称                    | 角色                                             | 默认状态 | 拆分原因                                                                               |
| :-------------------------- | :----------------------------------------------- | :------- | :------------------------------------------------------------------------------------- |
| **`dsh-zotero`（核心）**    | 本地通信、基础模型工具、文献轨迹、设置页         | 启用     | 插件主体，提供底层连接与基础能力。                                                     |
| **`dsh-zotero/library`**    | 文献面板服务（`zoteroLibrary`）与右侧边栏界面    | 启用     | 将全库浏览界面独立拆出，支持整体关闭，并有独立的设置项。                               |
| **`dsh-zotero/scholarly`**  | 外部学术检索、开放获取全文读取、引文核验         | 关闭     | Agent 外部学术检索授权边界，启用后才允许请求白名单索引与开放获取 PDF 臂。              |
| **`dsh-zotero/enrichment`** | 主动 MinerU 文档解析、已有产物复用与本地语义排序 | 关闭     | 启用即接受 MinerU 文档外发并提供解析与模型管理能力；上传仍需用户针对具体文档主动提交。 |

### 组件分工

- **核心组件**：插件主体。管理与本地 Zotero API（`127.0.0.1:23119`）的通信，注册 8 个读取工具与 15 个写入工具，维护文献轨迹与配置项。
- **文献面板组件**：向前端提供只读与写入端点（`browse`、`search`、`item` 等），自身不注册工具，不注入提示词段，本地库操作转交核心服务；用户主动阅读 URL PDF 使用独立的 `allowUrlPdfRead` 授权与公网下载边界。不需要侧边栏时可以整体卸载。
- **学术检索组件**：控制 Agent 外部学术检索授权。未启用时，不注册学术检索工具或提示词段，也不发起学术检索请求；启用后注册 7 个学术检索工具：索引检索严格限制在预设的白名单学术索引内，开放获取 PDF 全文臂是唯一例外，可访问任意公网 HTTP(S) 主机（受公网地址双门校验，见[架构](architecture.md)）。
- **文档解析组件**：提供主动解析、已有产物查询与本地语义模型管理。启用组件即接受 MinerU 文档外发；客户端在组件处于已启用状态且本机尚未确认时显示外发提醒，确认后按浏览器持久记住。组件不注册模型工具、不注入提示词段。普通 `zotero_retrieve` 与 `scholarly_read` 仅通过核心的只读 `FulltextEnhancer.lookup` 查询同一来源、仍有效的 Markdown；命中时优先使用，未命中时继续原有 Zotero 全文索引或已获准的 PDF 下载与本地抽取。本地语义排序独立于 MinerU；主动解析也不需要语义模型。

`src/skills/` 通过 Harness 可选的 `ctx.skills` 注册分阶段指令，核心组件持有 3 个，学术检索组件持有 4 个。模型先从只含名称与短描述的目录中选择，再经 `skill` 工具加载完整 Markdown 正文；正文不进入常驻 system prompt。详见[研究 SOP 技能参考](skills.md)。

### 主动解析契约

以下说明描述当前的 enrichment 实现。

启用组件即接受 MinerU 文档外发；组件挂载不发起上传。用户针对一个具体 Zotero PDF 附件（子附件或顶层附件）或一个公开 PDF URL 提交，宿主检查远程动作与会话访问权限。提交前展示目标、MinerU、所选模式、上传含义与限制；不自动选择父条目下的所有 PDF，不接受主机路径、会话文件或调用方提供的原始字节。文献面板的 URL PDF 阅读许可与 scholarly 授权不构成 MinerU 解析许可。

普通读取、PDF 打开、设置保存和服务启动不创建或恢复 MinerU 任务，也不上传文档。已有且有效的产物始终可读取；无产物或源已变化时，读取原索引或本地抽取文本。主动发起的解析失败时不切换模式，也不以本地文本冒充成功。

主动解析由 `ctx.jobs` 承载会话所属任务，提供进度、取消与有界回执；界面通过类型化端点提交，不调用模型工具。关闭界面只释放观察；取消、会话关闭和组件卸载撤销对应等待者；共享解析在最后一个等待者离开后中止并等待清理。已接纳的前台读取按原期限排空，模型切换或卸载不提前释放其资源。不增加旧组件、配置、缓存格式或接口的别名与迁移。

## 数据流

```mermaid
graph LR
    U[用户] --> P[文献面板]
    A[Agent] --> T[模型工具]
    P --> LS[zoteroLibrary 服务]
    T --> S[ctx.zotero 核心服务]
    LS --> S
    S --> Z[Zotero 本地 API]
    Z --> L[本地 Zotero 文献库]
    A -.->|工具调用快照| TR[文献轨迹]
    U --> TR
    A --> X[学术检索组件] --> E[外部学术索引]
    S -.->|只读 lookup| PA[文档解析组件]
    U -.->|具体附件或公开 URL 主动提交| PA
    PA -.->|组件启用授权与具体文档提交| M[MinerU 外部解析服务]
```

两条主通路均通过 `ctx.zotero` 访问本地文献库。Agent 外部学术检索仅在 scholarly 组件启用时生效。用户主动阅读库内 URL PDF 由文献面板的独立授权控制，不启用 scholarly。图中 enrichment 路径即当前实现：普通读取只查询已有产物，只有用户主动提交的具体目标才进入解析任务并产生外部请求。

## 四条边界

1. **写入安全**：写入工具默认关闭。开启后只能修改个人库（`zotero://user/0/`）；无论来自 Agent 还是面板，每次写入都要经过审批和计划卡确认，失败不自动重试。
2. **网络隔离**：本地请求走环回地址（`127.0.0.1`），不跟随重定向；Agent 外部学术检索由 scholarly 组件授权，索引检索限白名单，开放获取 PDF 臂可访问公网 HTTP(S) 主机。用户主动阅读库内 URL PDF 另受 `allowUrlPdfRead` 授权；两类 PDF 下载逐跳校验公网地址与 DNS 固定连接。MinerU 上传要求 enrichment 已启用、用户提交具体文档并通过宿主访问门禁；组件启用不发起上传，普通读取不构成 MinerU 解析授权。API 动态返回的签名上传与结果 CDN 地址视为不可信输入，同样逐跳校验公网地址与 DNS 固定连接；凭据仅发往固定 MinerU API 主机。
3. **轨迹范围**：文献轨迹只记录当前会话的读操作和导出；写入由审批卡记录，不进轨迹；外部检索到的文献在保存进库前，也不计入轨迹。
4. **作用域**：回收站只有面板能查看，模型工具不检索回收站；面板检索仅限于本地库，外部检索全部由 Agent 负责。

## 典型工作流

- **在对话中研读与核对**：在会话中向 Agent 提问，Agent 检索本地文献并提取带页码的原文片段；随后切到顶部的文献轨迹，核对查询条件与原文出处。
- **在侧边栏查阅与引用**：在右侧边栏打开文献面板，翻阅合集或筛选条目，阅读 PDF；动作行可直接复制 BibTeX 或 CSL 引用，也可以点「提问」把文献填入会话输入框。
- **查找与保存库外文献**：让 Agent 通过学术检索组件搜索外部索引、阅读开放获取全文；确认需要后保存到本地个人库，随后该文献即可在面板和轨迹中查看。

## 文献面板导航规则

合集与保存的搜索按层累计加载，加载更多保留已有节点。同库合集与全部条目之间默认保留关键词和附加筛选，可在文献面板设置中改为清空；切换库、保存搜索或回收站始终清空，保留检索模式与排序；重复选择当前范围和重新打开面板保留查询。展开按钮只展开，名称只选择；定位入口沿真实父链展开并加载当前合集。

用户主动阅读库内 URL PDF 由文献面板的独立授权控制，只解析已有附件并在点击后下载，不启用外部学术检索。共享设置与浏览位置分开：设置由 profile 保存，位置按当前浏览器、Zotero 实例及会话保存。
