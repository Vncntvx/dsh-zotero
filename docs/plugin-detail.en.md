- Core component (`dsh-zotero`): the local Zotero connection, 8 read tools and 15 write tools (off by default; once enabled, every write needs confirmation on the plan review card), the literature trail, and the settings page.
- Literature panel (`dsh-zotero/library`): a right-sidebar tab covering whole-library navigation (collection tree, saved searches, My Publications, Trash), item list filters, item inspection, citation copying (CSL citation, BibTeX, bibliography, BibLaTeX, RIS, CSL-JSON, and item info), and approved controlled writes.
- Scholarly search (`dsh-zotero/scholarly`): the external literature retrieval component, off by default; mounting the component is what authorizes requests to the external academic indexes. It covers arXiv, OpenAlex, Crossref, Semantic Scholar, PubMed, Europe PMC, and DBLP, with full-text reading, citation graphs, reference verification, and saving to Zotero.
- Document parsing (`dsh-zotero/enrichment`): the optional document-enrichment component, off by default; mounting provides user-submitted MinerU parsing, existing-artifact reuse, and local semantic ranking / model management and authorizes no document upload. Ordinary reads use the core's read-only `FulltextEnhancer.lookup` to find valid Markdown for the same source; a MinerU parse starts only after the user submits one specific Zotero PDF attachment (child or top-level) or one public PDF URL, with the deployment gate `allowDocumentUpload` (off by default) plus remote-action and session access checks. It supports the token-free `free` lightweight API and the token-gated `pro` precise API, and stores parsed Markdown in a configurable local directory. Local semantic ranking is independent of MinerU; with semantic search on but the model unready, a read fails with an error instead of falling back to BM25. The component registers no model tools and injects no prompt section.
